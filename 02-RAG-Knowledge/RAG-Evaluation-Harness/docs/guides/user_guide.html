What This App Is

AI_RAGAS is a small Python project for evaluating a RAG system with RAGAS metrics. It sends one or more questions to a configured RAG endpoint, collects the generated answer and retrieved context documents, and scores the result with an OpenAI-compatible LLM endpoint.

The project can be used in two ways: through a Streamlit web interface for interactive review, or through pytest/script files for automated metric checks.

RAG Endpoint

The app sends a question to RAG_ENDPOINT. The endpoint is expected to return an answer plus retrieved documents.

RAGAS Metrics

The app evaluates retrieval, augmentation, and generation quality using RAGAS no-embedding metrics.

LLM Judge

The scoring step uses an OpenAI-compatible model configured through LLM_API_ENDPOINT, LLM_MODEL, and OPENAI_API_KEY.

How It Works

  1. You provide a question and a ground-truth reference answer.
  2. The app calls the configured RAG endpoint with the question.
  3. The RAG endpoint returns a generated answer and retrieved documents.
  4. The app converts that data into a RAGAS SingleTurnSample.
  5. Selected RAGAS metrics ask the configured LLM judge to score the sample.
  6. The app displays metric scores, the answer, reference, and retrieved contexts.
Important: The quality of the score depends on the question, the reference answer, the retrieved contexts, and the LLM judge configuration.

Configuration

The app loads configuration from 1.env in the project root. Create or update that file before running the app. 

OPENAI_API_KEY=your-llm-api-key
LLM_API_ENDPOINT=https://your-openai-compatible-endpoint/v1
LLM_MODEL=your-model-name
LLM_TEMPERATURE=0
LLM_MAX_TOKENS=8192
RAG_ENDPOINT=https://your-rag-service/ask

QUESTION=How many articles are there in the Selenium webdriver python course?
REFERENCE_ANSWER=There are 23 articles in the Selenium WebDriver Python course.
Setting Description
OPENAI_API_KEY API key for the LLM judge endpoint.
LLM_API_ENDPOINT OpenAI-compatible base URL or completion URL. The code normalizes common completion suffixes.
LLM_MODEL Model name passed to RAGAS through the OpenAI-compatible client.
LLM_TEMPERATURE Judge model temperature. Use 0 for more repeatable scores.
LLM_MAX_TOKENS Maximum judge-model output tokens. The UI defaults to 8192 if omitted.
RAG_ENDPOINT Endpoint that receives the question and returns the RAG answer and retrieved documents.
QUESTION Default single-question value used by some standalone scripts.
REFERENCE_ANSWER Default ground-truth answer used by some standalone scripts.
Do not commit real API keys to source control. Treat 1.env as a local secrets file.

Run The Streamlit UI

1. Open PowerShell In The Project Folder

cd D:\RMFolder\RMPythonProjects\AI_Training\AI_RAGAS

2. Create A Virtual Environment If Needed

py -m venv .venv

3. Install Dependencies

& .\.venv\Scripts\python.exe -m pip install -r .\requirements.txt

4. Start The UI

& .\.venv\Scripts\streamlit.exe run .\Test5_allwithUI.py

5. Open The Browser

Streamlit normally opens automatically. If it does not, open: 

http://localhost:8501

Run Metric Tests

Use these commands from the project root after installing dependencies.

Run All Main Metrics

& .\.venv\Scripts\python.exe -m pytest -q .\Test5_all.py -s

Run Context Recall

& .\.venv\Scripts\python.exe -m pytest -q .\Test2_contextrecall.py -s

Run Faithfulness

& .\.venv\Scripts\python.exe -m pytest -q .\Test4_faithfullness.py -s

Run Factual Correctness

& .\.venv\Scripts\python.exe -m pytest -q .\Test5_factualcorrectness.py -s

Several scripts can also be run directly with Python, for example: 

& .\.venv\Scripts\python.exe .\Test2_contextrecall.py

Using The UI

Config Tab

  • Confirm the LLM model, API endpoint, temperature, and max tokens.
  • Select the metrics you want to run.
  • Add or edit rows in the question and ground-truth table.
  • Click Step 1: Query RAG and Review.

Step 1 Review

The app calls the RAG endpoint and shows the query, generated response, reference answer, and retrieved contexts. Review these values before scoring. You can edit the fields if the endpoint returned noisy text or if you want to test a corrected sample.

After reviewing the data, click Step 2: Run Metrics.

Results Tab

The results tab shows a summary table, score cards, and row-level details. Expand a row to inspect the exact query, answer, ground truth, and retrieved contexts used for scoring.

Metric Tab

The metric tab explains each selected metric, required inputs, scoring idea, and how to interpret low or high values.

Metrics Explained

Metric Area What It Checks Recommended Score
Context relevance Retrieval Whether retrieved contexts are relevant to the user query. 0.80 to 1.00
Context precision with reference Retrieval Whether retrieved contexts are useful for supporting the reference answer. 0.80 to 1.00
Context recall Retrieval Whether retrieved contexts contain the facts needed by the reference answer. 0.80 to 1.00
Response groundedness Augmentation Whether the generated response is supported by retrieved contexts. 0.80 to 1.00
Faithfulness Augmentation Whether response claims are consistent with retrieved contexts. 0.85 to 1.00
Factual correctness Generation Whether the generated response matches the ground-truth reference. 0.70 to 1.00

Troubleshooting

Missing Required Setting

If you see Missing required setting, check that 1.env exists in the project root and contains the required variable.

RAG Endpoint Failure

If Step 1 fails, verify RAG_ENDPOINT, confirm the service is online, and check that it accepts JSON shaped like this: 

{
  "question": "your question",
  "chat_history": []
}

LLM Scoring Failure

If Step 2 fails, verify OPENAI_API_KEY, LLM_API_ENDPOINT, and LLM_MODEL. If the error mentions output length, increase LLM_MAX_TOKENS or shorten the reference/context text.

Low Scores

Low retrieval scores usually mean the RAG system retrieved missing or irrelevant context. Low faithfulness or groundedness scores usually mean the answer contains unsupported claims. Low factual correctness usually means the answer does not match the ground truth.
