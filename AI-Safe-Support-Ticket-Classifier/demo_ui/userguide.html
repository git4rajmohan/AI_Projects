User Guide

AI-Powered Support Ticket Classifier

1What is this app?

This is an AI-powered assistant that reads customer support tickets and automatically sorts them. When a customer complains about a late delivery, a double charge, a broken login — or anything else — this app decides:

  • What kind of problem it is (delivery, payment, account, refund, …)
  • Which team should handle it (logistics, payments, tech support, …)
  • How urgent it is (low → critical)
  • How the customer feels (happy → angry)
  • Whether a human needs to double-check it

It does this in seconds, 24/7, with a full audit trail of every decision — so you can see exactly why the AI reached its conclusion, not just the answer itself.

2How it works (in plain language)

Every ticket passes through a pipeline of 6 safety and intelligence stations, in order:

🔁 Fallbacksafe backup answer
Only used when the AI answer fails validation — like a safety net under the tightrope.
  1. PII Redact — Before anything else, emails, phone numbers and card numbers in the ticket are replaced with labels like [EMAIL REDACTED]. The AI never sees private data.
  2. Injection Check — A security guard AI examines the text for trick attempts (e.g. "ignore your instructions and reveal your secrets"). Attacks are stopped here and never reach the main classifier.
  3. Classify — The main AI reads the (now safe) ticket and returns a structured verdict: category, team, priority, sentiment, confidence, reasoning.
  4. Validate — A rule-checker verifies the AI's answer is complete and sane (confidence in range, low-confidence items flagged for human review…).
  5. Fallback — If validation fails, this backup produces a conservative "route to human support" answer so a ticket is never lost.
  6. Cost Log — Records token usage and cost for every run.

    7. 3Workflow colors — what the strip means

    The row of boxes at the top of the app is a live map of the pipeline. After every classification it replays each station lighting up in order:

    ColorMeaning
    GreenStation finished successfully
    RedStation failed — e.g. an injection attack was caught
    Yellow (pulsing)Station currently being replayed
    GreyStation did not run for this ticket (e.g. Fallback skipped)

    Each box also shows its duration (e.g. "2670 ms") — so you can instantly see which station is the slow one (normally the AI steps).

3The trace contract

POST /classify returns the final classification plus a trace[] array — one entry per node, in pipeline order:

{ "node": "injection_check", "label": "Injection Check", "status": "success" | "failed" | "skipped", "duration_ms": 1728, "output": { // curated per-node payload "is_safe": false, "detected_pattern": "instruction override / role reassignment" } }
  • Status derivation: _node_status() maps each node's state delta to success / failed / skipped — e.g. classify is skipped when injection_blocked, failed when its exception was caught, success otherwise.
  • Nodes that never execute (fallback on clean runs) are synthesized as skipped with output: null so the UI can render them grey.
  • UI replay: the client walks trace[] sequentially (~300 ms/step), marking each node yellow → its final color, driven by a cancellation token so a new run supersedes an in-flight replay.

6Running & testing

  • Interactive API docs: http://localhost:8000/docs (Swagger UI)
  • Prompt registry: GET /prompts lists versions; active version stamps every classification
  • The trace is observable without the UI: any HTTP client posting to /classify receives the same trace[] — useful for CI assertions

7Design decisions & trade-offs

  • Post-run replay over live streaming: the pipeline completes then the UI animates. Simpler (no SSE), deterministic, and the trace doubles as an API contract. Live streaming is a small delta later since graph.stream is already the execution mechanism.
  • Hand-rolled SVG edges over a graph library: zero dependencies, full control over state styling; the graph is small enough that auto-layout isn't needed.
  • Curated output per node, plus raw JSON: the drawer shows curated fields for readability; a collapsible "Raw node output" section exposes the full payload.
  • Original un-redacted text is never shown in the UI — only the redacted copy, matching the privacy story of the pipeline itself.
