🛰️ Remote A2A Agent Explorer — Meet Other People's Agents

Python · Streamlit · a2a-sdk 1.3.0 · Ollama Cloud: a local web app where you discover publicly hosted A2A agents in a real registry, inspect their Agent Card, validate them in five staged checks (card → protocol → endpoint → authentication → task), save them to SQLite, and delegate real tasks that flow over HTTPS using the Agent-to-Agent protocol. Results come back attributed to the remote agent that produced them, with a task ID, live status trail, structured JSON, and honest warnings for auth-required and paid (x402) agents. Everything remote output says is treated as untrusted data — shown, never executed. A local two-agent demo (demo.py) proves the plumbing before you ever touch a stranger's server, and 64 offline tests guard it all — all installed inside one .venv, all secrets in .env, and every saved agent remembered in agents.db between sessions. Beyond the web UI, the same journey runs from the command line (remote_agents_cli.py discover/save/task) including parallel delegation to two saved agents at once with per-agent attribution, which the coordinator presents with each remote agent's name and task ID.

The 30-second pitch

AI agents are appearing all over the internet, but calling someone else's agent is nothing like calling your own: you don't know its address, what it can do, whether it speaks your protocol, whether it wants a password — or whether the thing at that URL is even an agent at all and not just a webpage or a REST API wearing a trench coat. Pointing your code at a pasted URL and hoping is how integrations break.

The Remote A2A Agent Explorer is that first meeting, handled properly. You search a real public registry (a2aregistry.org) or paste any Agent Card URL; the app fetches the card safely (SSRF-guarded, no redirects, size-capped), validates it against the official A2A schema, walks the five staged checks and only then — with your explicit choice — sends a genuine A2A task over HTTPS and tracks its lifecycle (SUBMITTED → WORKING → COMPLETED). Results are attributed to the remote agent with their task ID, structured JSON renders safely, agent-only replies are labeled, and paid-tool offers (x402 micropayments) get a loud warning that nothing was charged or sent. Every step of validation has its own pass/fail badge — a fetched card is never mistaken for a working connection.

The line that matters: the directory finds candidates, the card advertises, the validator proves — and only the remote agent's own completed task counts as interoperability. A web page answering 200 OK proves nothing.

The one-line principle

🪪 Validate in stages, never in bulk

Five independent badges: Card · Protocol · Endpoint · Authentication · Task execution. Each can fail alone with its own reason — so "the card is fine but the endpoint is dead" reads exactly like that, and nothing is called connected until a real task completes.

🛡️ Treat every URL as an attack

Any URL you paste is checked before one byte leaves your machine: HTTPS enforced, loopback/private/ link-local/cloud-metadata IPs blocked by resolved address, redirects refused, response size capped. ALLOW_LOCAL_AGENTS=true is the only door for localhost — used by local dev and tests, never by default.

🧾 Remote output is untrusted data

Whatever the remote agent returns is displayed verbatim, attributed, and inert: no code runs, no instructions inside results are followed, artifact files are listed but never auto-downloaded, and an agent asking for money gets shown the door with a warning — not a payment.

What is this project?

The Remote A2A Agent Explorer is a matchmaking desk for AI agents: you tell it who you need (search words, a pasted URL), it introduces vetted candidates from a public registry, inspects their credentials (the Agent Card), checks the phone line (the endpoint), and then — with your OK — places real work orders (A2A tasks) and hands you back each report stamped with who produced it and its task number. Your own local agents (powered by Ollama Cloud) stay yours; the remote ones belong to completely different operators, and the app never forgets that.

Using it is three moves:

  1. Discover — search the registry (empty box = all 50+ agents) or paste an Agent Card URL — even a registry web-page link works, it resolves to the real card automatically. You get a five-badge validation report plus the full card details.
  2. Connect — save the agents you like (SQLite, metadata only), toggle trusted/untrusted, refresh their cards any time, add a bearer token only if the agent asks for one.
  3. Delegate — pick an agent, type a task in plain words, press Send A2A Task and watch the status trail (SUBMITTED → WORKING → COMPLETED) until the attributed result lands. The coordinator's remote/parallel modes do the same from the command line.

Think of it as an embassy staffed by three specialists: a receptionist who only accepts URLs that pass the metal detector (SSRF checks), a notary who reads each visitor's diplomatic card (Agent Card) and refuses anything that's obviously a tourist in a suit (websites, REST APIs, MCP servers pretending), and a courier who carries your task to the remote agent and returns with a signed receipt — agent name, task ID, verbatim output. The courier never opens your wallet: a paid-tool offer comes back labeled "nothing was charged or sent."

The honest limits: remote agents are other people's servers — they go offline, change terms, throttle, or quietly demand payment. The app surfaces all of that (badges, warnings, timeouts) rather than pretending otherwise, and public internet reachability means the offline test suite stays mock-based on purpose. Streaming and push notifications are used only when the remote agent advertises them; everything else degrades to polling with a hard timeout.

What does working with it look like?

The app is a single Streamlit page at http://localhost:8511 (or 8501). Three tabs carry the three moments: 🔍 Discover (search + URL entry + validation badges + save), 📤 Send Task (agent picker, task box, token field, live status, result), 💾 Saved Agents (trust toggles, refresh, remove, history). Buttons go live only when their inputs are ready, and every failure shows one readable sentence — the app stays usable after any error.

The 6-step workflow

1

Set up — once

.venv → pip install -r requirements.txt → copy .env.example to .env.

Python 3.11+. The only secret you need is OLLAMA_API_KEY from ollama.com/settings/keys — that's what powers the local demo agents over Ollama Cloud. It is never sent to any remote agent. Nothing else to install; the A2A SDK, Streamlit and friends come from requirements.txt.

2

Smoke the plumbing locally

smoke_test.py (LLM answers "pong") then demo.py (two local agents talk A2A).

Before trusting strangers, watch your own two agents shake hands: demo.py starts the local worker agent, the coordinator resolves its card, sends a task over A2A, and prints the answer. This is the baseline that proves the SDK wiring — the remote explorer you're about to use is exactly this, plus guards.

3

Launch the explorer

streamlit run webui.py → open the URL in your browser.

Running a local worker for comparison? Start it first and set ALLOW_LOCAL_AGENTS=true in that terminal — without it, every non-public URL (localhost, private IPs) is refused on purpose. For public third-party agents, no special setting is needed.

4

Discover — every candidate earns its badges

Search word (or empty for the full registry) → Inspect Agent Card, or paste a URL → Discover Agent.

Each candidate shows provider, skills and card URL; inspecting runs the staged validation: ✅ VALID card, ✅ SUPPORTED protocol, ✅ REACHABLE endpoint, ⚪ auth, ⚪ NOT TESTED task. A card that's missing fields or a webpage that isn't a card at all gets one plain sentence, never a half-broken import. Save the good ones with one click.

5

Send a task — the real interoperability test

Pick a saved agent, phrase the task around one of its advertised skills, press Send A2A Task.

The status trail fills in as the remote agent reports (SUBMITTED → WORKING → COMPLETED); the result card shows agent name, task ID, verbatim text, structured JSON, and artifact metadata ("not downloaded"). Message-only replies explain themselves ("no task ID"); paid-tool offers get the yellow "nothing was charged or sent" warning. Everything is recorded in the agent's history automatically.

6

Manage & audit — Saved Agents

Trust toggle · Refresh card · 🗑️ Remove · Task history per agent.

Trusted is your mark, not the agent's. Refresh re-fetches and re-validates the card (agents do change their terms). Remove deletes the agent and its history. The history is your audit trail: what you sent, when, the task ID, the state, and a summary of what came back — none of it contains secrets.

Architecture

Every concept owns one file; the app is glue around the official a2a-sdk 1.3.0. The Streamlit page (webui.py) and the CLI (remote_agents_cli.py, coordinator.py) call the same functions — there is no second brain.

Task lifecycle handling

How send_task() runs a task

  • SSRF-revalidates the advertised endpoint, then builds an SDK ClientFactory client.
  • Streaming when both sides advertise it; otherwise poll get_task every A2A_POLL_INTERVAL_SECONDS.
  • Hard asyncio.timeout → state TIMEOUT at A2A_TASK_TIMEOUT_SECONDS; no infinite polling.
  • Stream events absorbed per-payload: task, message, artifact_update, status_update.

The states you can see

  • SUBMITTED → WORKING → COMPLETED / FAILED / CANCELED / REJECTED.
  • Message-only exchanges (no Task object) surface as "message-only reply (no task ID)", state COMPLETED when content exists.
  • Every state change fires the progress callback → the UI's live status trail.
  • cancel_task() exists for agents that support cancellation.

  • "HTTPS is required": an http:// URL in public mode — intended; local mode for dev only.
  • "resolves to non-public address": SSRF guard — the host is loopback/private/metadata.
  • "agent rejected the request as unauthorized": missing/invalid bearer token; check the card's auth scheme.

  • Stale imports after edits: restart Streamlit — a running server keeps old modules cached.

Design decisions & trade-offs

  • SDK first, always — cards parse through a2a.parse_agent_card, tasks through ClientFactory; the app invents no protocol messages and no registry endpoints (the registry adapter ships only after its API was verified live).
  • Five gates, visibly separate — a valid card with a dead endpoint displays exactly that; task_ready needs protocol and endpoint to pass, and "Task execution" only ever turns green from a real completed task.
  • Message-only replies are a first-class case — several real agents answer without creating a Task; the client detects it and says so instead of printing a mysterious empty ID.
  • One guard, one place — validate_url() wraps every outbound call (cards, endpoint probes, registry lookups, delegation), so a new feature inherits SSRF safety by default.
  • Verified registry adapter — a2aregistry.org has no server-side search, so filtering is client-side over the documented /api/agents list; registry page URLs resolve through the documented per-agent endpoint. No scraping, no guessed paths.
  • Parallel delegation is explicit — delegate_parallel takes agent ids you named; results combine per-agent with attribution via present_many. No automatic fan-out, ever.
  • Paid offers end at the label — x402-style intent: "paid_tool" payloads are detected by metadata, warned about loudly, and never executed; payment is a deliberate non-goal.
