RAG Evaluation Reference

Metrics Guide

This guide summarizes the six RAG metrics used in this project, the RAG stage each belongs to, the inputs each metric consumes, a conceptual formula, and a simple example showing what a low-score and high-score case looks like.

Note: these formulas are conceptual. Ragas uses LLM-based judging under the hood, so the exact score is not a strict arithmetic count, but these formulas are a good mental model for understanding what the metric is trying to measure.

Metric RAG Stage Inputs Recommended Range Conceptual Formula
Context relevance Retrieval Query + Retrieved contexts 0.80-1.00 relevant retrieved contexts / total retrieved contexts
Context precision with reference Retrieval Query + Reference + Retrieved contexts 0.80-1.00 contexts supporting reference / total retrieved contexts
Context recall Retrieval Query + Reference + Retrieved contexts 0.80-1.00 reference claims supported by contexts / total reference claims
Response groundedness Augmentation Response + Retrieved contexts 0.80-1.00 response claims supported by contexts / total response claims
Faithfulness Augmentation Query + Response + Retrieved contexts 0.85-1.00 response claims consistent with contexts / total response claims
Factual correctness Generation Response + Reference 0.70-1.00 response claims matching reference / total evaluated claims

Context Relevance

Retrieval
What it checks
Whether the retrieved contexts are on-topic for the user query.
Inputs
Query + Retrieved contexts
Formula
relevant retrieved contexts / total retrieved contexts
Example
Query: What is the capital of France?
Retrieved contexts: 1 chunk says Paris is the capital of France, 1 chunk discusses France in Europe, and 2 chunks talk about Germany and Italy.
Low score case: much of the retrieved context is about other countries and not the capital of France.
High score case: nearly every retrieved chunk directly talks about France and explicitly mentions Paris as the capital.
Root Cause

Your search engine is fetching junk. It is pulling documents that share keyword overlap with the query but are contextually useless.

What to Fix
  • Tune Chunking Strategy: Your data chunks might be too large (mixing topics) or too small (losing context). Try switching to semantic chunking or a parent-child retriever pattern.
  • Adjust Hybrid Search Weights: If you use BM25 + Vector embeddings, your keyword match might be overpowering your semantic match. Adjust the weight ratios.

Context Precision With Reference

Retrieval
What it checks
Whether the retrieved contexts are specifically useful for supporting the expected answer.
Inputs
Query + Reference + Retrieved contexts
Formula
contexts supporting reference / total retrieved contexts
Example
Reference: The capital of France is Paris.
Retrieved contexts: 1 chunk states Paris is the capital of France, while 3 other chunks discuss French food, tourism, and the Eiffel Tower.
Low score case: only one retrieved chunk directly supports the reference and the rest are extra information.
High score case: most retrieved chunks directly support the reference that Paris is the capital of France.
Root Cause

The correct document is being found, but it is buried at the bottom of the pile (e.g., position #5 instead of position #1). The most useful chunk is not ranked first.

What to Fix
  • Implement a Re-ranker: Introduce a Cross-Encoder re-ranking step (like Cohere or BGE-Reranker) right after initial retrieval to force the most relevant chunks to the top before they reach the LLM.

Context Recall

Retrieval
What it checks
Whether retrieval brought back enough information to cover the facts in the reference answer.
Inputs
Query + Reference + Retrieved contexts
Formula
reference claims supported by contexts / total reference claims
Example
Reference: The capital of France is Paris.
Retrieved contexts: one chunk says France is a country in Europe, and another chunk describes Paris as a famous tourist city, but no chunk explicitly says Paris is the capital of France.
Low score case: retrieval brings related information but misses the key fact needed to fully support the reference.
High score case: retrieval explicitly includes the sentence that Paris is the capital of France.
Root Cause

Your search engine missed the answer entirely. The necessary information is completely missing from the retrieved context.

What to Fix
  • Increase K: Bump up the number of retrieved chunks (e.g., from Top-3 to Top-5 or Top-7).
  • Fix the Vector Store Index: Ensure your document ingestion pipeline did not fail, skip files, or corrupt text during parsing (check PDF/OCR extraction quality).
  • Query Rewriting: Add an LLM step to rewrite or expand the user's query into multiple variations before executing the search.

Response Groundedness

Augmentation
What it checks
Whether the generated response is backed by the retrieved context.
Inputs
Response + Retrieved contexts
Formula
response claims supported by contexts / total response claims
Example
Response: The capital of France is Paris, and France has 80 states.
Retrieved contexts: the contexts say Paris is the capital of France, but they do not mention anything about 80 states.
Low score case: part of the response is unsupported by the retrieved evidence.
High score case: the response only says that the capital of France is Paris, and that statement is clearly supported by the contexts.
Root Cause

The LLM is hallucinating or relying on its own pre-trained weights rather than restricting itself to the provided context.

What to Fix
  • Tighten System Prompt Constraints: Use explicit, defensive framing: "Base your answer strictly on the provided context. If the context does not contain the answer, state 'I do not know.' Do not use any outside knowledge."
  • Lower Temperature: Drop the LLM's temperature configuration to 0.0 or 0.1 to force deterministic text generation.

Faithfulness

Augmentation
What it checks
Whether the response stays consistent with the retrieved context and avoids hallucination.
Inputs
Query + Response + Retrieved contexts
Formula
response claims consistent with contexts / total response claims
Example
Retrieved context: Paris is the capital of France.
Response: The capital of France is Lyon.
Low score case: the response contradicts the retrieved context, so it is not faithful.
High score case: the response says the capital of France is Paris, which matches the retrieved context exactly.
Root Cause

The LLM is hallucinating or relying on its own pre-trained weights rather than restricting itself to the provided context.

What to Fix
  • Tighten System Prompt Constraints: Use explicit, defensive framing: "Base your answer strictly on the provided context. If the context does not contain the answer, state 'I do not know.' Do not use any outside knowledge."
  • Lower Temperature: Drop the LLM's temperature configuration to 0.0 or 0.1 to force deterministic text generation.

Factual Correctness

Generation
What it checks
Whether the response matches the expected ground-truth reference.
Inputs
Response + Reference
Formula
response claims matching reference / total evaluated claims
Example
Reference: The capital of France is Paris.
Response: The capital of France is Lyon.
Low score case: the response contradicts the reference on the key fact.
High score case: the response says the capital of France is Paris, matching the reference.
Root Cause

The final answer contradicts your gold-standard Ground Truth reference data.

What to Fix
  • Verify the Reference Data First: Always double-check if the Ground Truth itself is still accurate, updated, and free of typos before blaming the model.
  • Trace the Retrieval Link: Look at Context Recall. If Recall is low, Factual Correctness will almost always be low because the model did not have the facts to begin with. Fix the retrieval step first.
  • Upgrade the Model Size: Small, open-source models often struggle to accurately synthesize reasoning across multiple facts. Consider testing against a larger parameter model (e.g., upgrading from an 8B to a 70B parameter model) to see if reasoning accuracy improves.
